### 5.3 前端JS自动加载机制

后台采用 RequireJS 模块化加载：

1. `Common.php` 的 `viewInit()` 计算当前控制器对应的JS路径
2. 路径规则：`public/static/admin/js/{controller_path}.js`
3. 页面加载时自动执行 `Controller.{action}()` 方法

```javascript
define(["jquery", "easy-admin"], function ($, ea) {
    var Controller = {
        index: function () {
            ea.table.render({ elem: '#currentTable', url: 'crm.customer/index', cols: [[...]] });
            ea.listen();
        },
        add: function () { ea.listen(); },
        edit: function () { ea.listen(); }
    };
    return Controller;
});
```

## 7. API接口文档

### 7.1 认证机制

- **认证方式**：JWT Token（firebase/php-jwt 7.0）+ 数据库记录校验
- **Token传递**：HTTP Header 中携带 `token` 字段（请求头同时携带 `token_id` 便于排查）
- **Token获取**：登录接口返回 `token`、`token_id`、`expire`
- **过期处理**：Token过期返回 `{code:0, msg:"token已过期", statusCode:401}`

**单点登录机制（SSO）**

同一账号在同一时刻仅允许一台设备保持有效登录状态，核心规则：

1. **签发**：登录成功（`login/index`、`login/scan`）时由 `issueLoginToken()` 生成 32 位 `token_id` 写入 JWT payload，并在入库前删除该 admin_id 全部旧记录（旧设备 token 立即作废）；登录响应返回 `token_id` 供前端持久化（`vuex_token_id`）
2. **过期清理**：签发时顺带删除全表 `expire` 已到的记录（走 `idx_expire` 索引），防止离职/停用账号的过期 token 永久遗留；配合校验时的惰性删除，表规模稳定在「活跃账号数 + 近 14 天登录过的账号数」
3. **校验**：每次请求经 `Authority::initialize()` 调用 `Common::verifyTokenDb()`，同时校验 JWT 签名与 `admin_token` 表存在性；校验结果经 share 通道缓存 60s（`sso_token_{token_id}`，命中与未命中均缓存，避免每个请求多一次主键查询）；被顶替的 token 返回 `{code:0, msg:"账号已在其他设备登录", statusCode:401}`，前端据此提示并跳转登录页
4. **缓存一致性**：签发（顶替旧设备）、续签（token 内容更新）、注销、服务端过期删除记录后必须调用 `clearSsoTokenCache()` 清除 60s 缓存，否则顶替/退出后旧 token 最长 60s 仍可通过，或续签后新 token 被误判「被顶替」
5. **续签**：`ajax/refreshtoken` 保持 `token_id` 不变（不会自己踢掉自己），仅更新 JWT 与 expire，并同步清除校验缓存
6. **注销**：退出登录（`index/logout`）按 token_id 删除 `admin_token` 记录，token 立即失效
7. **WSS 联动**：登录签发时触发 `ssoTokenIssued` 事件，电话助手插件监听后通知 WSS 进程踢掉该 admin_id 下 token_id 不匹配的旧设备长连接（事件解耦，插件未安装时不影响登录）
8. **前端**：登录成功存储 `vuex_token_id`（随 `lifeData` 持久化），请求拦截器携带 `token_id` 头；401 时根据 msg 区分「被顶替」与「过期」分别提示，并清理 token/token_id/expire 后跳转登录

**请求示例：**
```
GET /api.php/crm.customer/index
Header: token: eyJhbGciOiJIUzI1NiIs...
Header: token_id: 9f2c...（32位hex，可选）
```

### 7.2 基础URL格式

```
http://your-domain/api.php/{控制器路径}/{方法名}
```

控制器路径使用点号分隔多级：
- `crm.customer/index` → `app/api/controller/crm/Customer.php` 的 `index` 方法
- `crm.contract_receivables/add` → `app/api/controller/crm/ContractReceivables.php` 的 `add` 方法
- `fields/get_fields` → `app/api/controller/Fields.php` 的 `get_fields` 方法

### 7.7 多选ID参数统一规范

项目中所有支持多选（批量操作）的功能，统一使用 **`ids`** 参数传递逗号分隔的 ID 列表。

**参数格式：**

```
POST /admin.php/crm.clue/toCustomer
Content-Type: application/x-www-form-urlencoded

ids=14,15,22    ← 逗号分隔，单个参数名
```

**前端 easy-admin.js 处理机制：**

| 模式 | 触发条件 | 参数传递方式 | 示例 |
|------|----------|-------------|------|
| `data-open` | 工具栏按钮 method:'open' + checkbox | URL 拼接 `?ids=` | `crm.clue/toCustomer?ids=14,15` |
| `data-request` | 工具栏按钮 method:'request' + checkbox | POST body `ids=` | `ids=14,15` |
| 行内按钮 | method:'request' + field:'' | URL 拼接 `?id={行ID}` | 单条语义，不走 ids |
| `data-table-export` | 导出按钮 | filter JSON `{"id":"1,2,3"}` | 走 filter/op 机制，不涉及 ids |

> **注意**：`data-request` 多选时，`field` 默认值为 `'id'`（从表格行数据提取 ID 字段），POST 参数名固定为 `'ids'`。两者是分离的，不可混淆。

**后端统一接收：`parseIds()` 函数**

位置：`app/common.php`，全局可用。

```php
/**
 * 归一化批量ID参数：统一多选ID参数格式（ids 优先，兼容旧 id）
 * 支持：标量(5)、逗号分隔字符串('1,2,3')、数组([1,2,3])
 * @return array intval过滤、去重后的ID数组
 */
function parseIds($ids = null)
```

**使用示例：**

```php
// 标准用法：自动从请求中读取 ids（兼容 id）参数
$id = parseIds();

// 多选删除
$row = $this->model->whereIn('id', $id)->select();

// 保持字符串形态（后续有 explode 或 where('pid','=',$id) 检查时）
$id = $this->request->param('ids', $this->request->param('id'));
```

**uniapp 移动端调用：**

```javascript
// 提交时传逗号分隔字符串，非数组
this.$u.post('crm.clue/toCustomer', { ids: '14,15' });
this.$u.post('crm.clue/delete', { ids: item.id });  // 单条也兼容
```

#### 未读提醒角标刷新机制

接口：`GET crm.reminder/getUnreadCount`，返回未读提醒数量 `count`、待办事项总数 `backlog`（8 类待办总和）及最新 5 条提醒列表。

统一入口为 `common/fa.mixin.js`（tools mixin）的 `refreshReminderBadge(force)` 方法：

- 请求成功后将未读数写入全局 `vuex_unread_count`（供头部消息通知位置绑定展示）；tabBar 配置包含提醒页时，同步更新 `vuex_config.tabbar.list` 中提醒项的 `count` 角标（fa-tabbar 组件 u-badge 渲染）；`backlog` 字段可用于移动端待办角标展示
- **节流保护**：模块级时间戳全局共享，30 秒内重复调用直接跳过；传入 `force=true` 可跳过节流强制刷新
- 未登录（无 `vuex_token`）时自动跳过，不发请求

**触发时机：**

#### 电话助手通话状态自愈机制（packageCall）

电话助手通过原生插件 `fhx-call`（原生拨号+录音）与全局模块 `common/fhx-call.js` 协同工作（该模块归属电话助手插件 file_map 管理，卸载插件时一并移走），通话状态事件流如下：

```
原生 CallService 状态机（1来电/2通话/3挂断/4来电未接/5去电未接/6占线）
  → CallModule UniJSCallback 回调
  → fhx-call.js 处理并广播 call:state 全局事件
  → packageCall/pages/call/index.vue 的 onCallState 订阅更新 UI
```

**问题背景**：App 进程被系统回收重建后，原生插件持有的 `UniJSCallback` 静态引用可能失效，导致挂断（status=3）回调永久丢失，页面卡在「呼叫任务中」。

**自愈机制（三层防线）：**

| 层级 | 机制 | 说明 |
|------|------|------|
| 回调层 | registerListener 重注册 | `isRegisterListener` 已为 true 时也会重新调用原生注册，刷新 JS 侧回调引用 |
| 动作层 | hangup() 5 秒自愈兜底 | 主动挂断后启动 5 秒定时器，超时未收到 status=3 回调则按当前状态手动收尾（任务上报/通话记录上报 + 清除状态），迟到的回调会被忽略（busy/currentCall 已置空） |
| 页面层 | onShow 同步 + 事件流中断检测 | 页面 onShow 时从全局模块重新同步 `callState`；若 5 秒后仍非 idle 且 15 秒内无任何状态事件，弹窗提示用户手动结束（不自动挂断，避免误挂真实通话） |

**原生状态机语义（CallService.java）：**

- 去电振铃（`RINGING` + 拨号标记）不再误判为来电响铃；来电/去电接通通过 `mLastIncoming` 区分上报
- 去电被拒接（振铃 → IDLE）正确上报 `ST_OUTGOING_MISSED(5)`，保证呼叫任务失败正常上报
- 占线通道上的来电结束（`mBusyRing` 标记）仅清除标记，不误触发通话收尾

#### 呼叫结果判定与手机端权限局限（call_result）

**呼叫结果枚举**（`addon_call_task.call_result`，手机端 `fhx-call.js` CALL_RESULT 与后台对齐）：

| 值 | 含义 | 说明 |
|----|------|------|
| 0 | 未知 | CallLog 探测失败（权限缺失/ROM 未写入/查询异常）时不臆断 |
| 1 | 已接通 | 任务上报 status=1 已执行，携带录音 |
| 2 | 无人接听 | 振铃超时（通常 45 秒以上）自然结束 |
| 3 | 对方忙线 | 仅 Telecom 托管模式（默认拨号器）可精确区分 |
| 4 | 被拒接 | CallLog type=5 可确定 |
| 5 | 拨号失败/网络异常 | 号码格式错误、无拨号权限、H5 端拦截等 |
| 6 | 用户主动挂断/取消 | 未接通前员工主动挂断；任务上报 status=3 失败、result=「用户主动挂断」 |

**判定数据源（按可靠性排序）：**

1. Telecom 托管事件（`source=telecom`）：携带 `disconnectCause` 与准确接通时长——仅默认拨号器模式下可用
2. 原生 CallService 状态回调（status=2/3/5）——部分 ROM 上推送回调可能系统性丢失
3. 系统通话记录 CallLog：`type=5` 可确定「被拒接」；`type=2` 且 `duration=0` 表示未接通
4. JS 看门狗轮询（2 秒采样 TelephonyManager 通话状态 + CallLog 对账）——回调丢失时的实际收尾路径

**手机端权限局限（重要）：**

- **华为 EMUI 等 ROM 不授予第三方应用「默认拨号器」角色**：`cmd role` 不跟踪 DIALER 角色、`CHANGE_DEFAULT_DIALER` intent 无处理者、Telecom `mDefaultDialerCache` 恒空，`FhxInCallService` 永不被系统绑定，因此**拿不到 Telecom 挂断原因（disconnectCause）**，通话界面与铃声仍由系统拨号器接管
- 非默认拨号器下 CallLog 对「员工挂断」与「无人接听」**均记为 `type=2、duration=0`**，无法直接区分二者
- 原生→JS 推送回调（status=2/3）在华为等 ROM 上丢失（`invokeAndKeepAlive` 静默失效），收尾依赖看门狗轮询，摘机/挂断时刻存在最多 2 秒采样误差

**振铃时长启发式判定**（应对上述权限局限，`DIAL_CANCEL_MAX_SEC = 40`）：

- 去电未接通（CallLog `duration=0`、非「被拒接」）时，以「振铃/OFFHOOK 时长」区分：
  - **< 40 秒 → 上报「用户主动挂断」**（call_result=6，任务 status=3 失败、result=「用户主动挂断」）
  - **≥ 40 秒 → 维持「无人接听」**（call_result=2）
- 阈值依据：员工挂断实测振铃约 5 秒；运营商无人接听振铃超时通常 45 秒以上，40 秒留有充足裕量
- **已知局限（透明说明）**：对方关机/停机/空号/忙线等快速结束的通话（5-20 秒）也会归为「用户主动挂断」；如需精确区分这些场景，需改造原生基座（Telecom 托管模式）或引导用户设置默认拨号器（华为 EMUI 等 ROM 不支持）

#### 插件数据表命名规范

新插件 `install.sql` 中创建的数据表**必须**以 `addon_{插件名}_` 为前缀（或恰好等于 `addon_{插件名}`），安装时系统会强制校验，不符合规范将阻断安装：

```sql
-- 正确（插件名为 demo，ymwl_ 为占位前缀，安装时自动替换为实际前缀）
CREATE TABLE IF NOT EXISTS `ymwl_addon_demo_log` (...);

-- 错误：未使用 addon_demo_ 前缀，安装时报错
CREATE TABLE IF NOT EXISTS `ymwl_demo_log` (...);
```

老插件白名单（`wechat`、`database`、`databaseapp`）豁免此校验，保持存量兼容。
统一前缀的意义：卸载时可按 `addon_{插件名}` 前缀扫描兜底清理，避免表残留。

### 9.4 插件主类（Plugin.php）

插件主类继承 `think\Addons`，提供四个生命周期钩子：

```php
<?php
namespace addons\database;

use think\Addons;

class Plugin extends Addons
{
    // 插件安装时执行
    public function install() { return true; }

    // 插件卸载时执行
    public function uninstall() { return true; }

    // 插件启用时执行
    public function enabled() { return true; }

    // 插件禁用时执行
    public function disabled() { return true; }

```

除生命周期钩子外，Plugin 类中**所有基类外的方法名都会被 think8-addons 自动注册为事件钩子**。全部公共钩子的完整使用说明（触发时机、参数约定、注册示例、核心调用点）见 **9.5 公共钩子开发指南**。

### 9.5 公共钩子开发指南

think8-addons 会自动将 Plugin 类中除基类（`think\Addons`）外的所有 public 方法名注册为事件钩子，任何插件定义同名方法即可共用同一钩子（多插件可共存，返回值由核心合并），核心调用点常驻布局/控制器、与插件生命周期无关。本章给出全部公共钩子的完整使用说明，新插件开发者可直接参照实现无缝集成。

#### 9.5.1 think8-addons 钩子机制概述

**注册原理**：插件系统服务 `ymwl/think8-addons` 经 `composer.json` 的 `extra.think.services` 在所有应用全局注册，每次请求启动时执行：

1. `Service::register()` 调用 `loadEvent()`，非 debug 模式下先读 `Cache::get('hooks')` 缓存的钩子注册表
2. 缓存为空时调用 `autoload()` 扫描所有已安装插件的 Plugin 类，将基类外的 public 方法名写入 `hooks` 注册表并 `Cache::set('hooks', $hooks)` 缓存
3. `Event::listenEvents($hooks)` 将钩子名与 `[插件类, 方法名]` 绑定为事件监听器
4. 钩子触发时框架以 `invoke` 调用插件方法，**传入单个参数**（无参数触发时方法无参）

**两种触发方式**：

| 触发方式 | 函数 | 返回值 | 适用场景 |
|---------|------|--------|---------|
| 模板钩子 | `hook('钩子名')` | 拼接字符串（join） | 后台布局脚本注入等 HTML/JS 输出场景 |
| 事件触发 | `\think\facade\Event::trigger('钩子名', $params)` | 数组（各监听者返回值集合） | API 数据合并、业务通知等结构化场景 |

**hooks 缓存清除注意事项**：非 debug 模式下钩子注册表缓存在 `hooks` 键，插件安装/卸载/启用/禁用后**必须**执行 `Cache::delete('hooks')` 清除，否则新钩子不会立即生效（参考 9.4 中 call 插件的 `clearHooksCache()` 实现）。开发环境（debug 模式）不读缓存，每次实时扫描。

#### 9.5.2 钩子总览

| 钩子名称 | 归属端 | 触发方式 | 参数 | 返回约定 |
|---------|--------|---------|------|---------|
| `adminLayoutScripts` | 后台 | `hook()` | 无 | string（纯 JS 片段） |
| `apiMenuItems` | 后端 API | `Event::trigger` | `$admin` 管理员数组 | array 菜单项 |
| `ssoTokenIssued` | 后端事件 | `Event::trigger` | `['admin_id','token_id']` | void |
| `appLaunch` | 手机端前端 | `invokeAppHooks` | `options` 启动参数 | void |
| `appShow` | 手机端前端 | `invokeAppHooks` | `options` 显示参数 | void |

#### 9.5.3 后台公共钩子

##### ① adminLayoutScripts（后台布局脚本注入）

- **【钩子名称】** `adminLayoutScripts`
- **【触发时机】** 后台布局 `default.html` 每次渲染时（所有后台页面共享该布局）
- **【参数说明】** 无参数；插件方法内通过 `app('http')->getName()` 与 `$this->request->action()` 自行判断应用与动作
- **【返回值约定】** 返回 string（纯 JS 片段，不含 `<script>` 标签，避免嵌套）；不满足条件时返回空字符串
- **【插件注册示例】**（`addons/demo/Plugin.php`）：

```php
public function adminLayoutScripts()
{
    // 插件未启用（禁用/卸载后目录仍存在）时不输出
    $info = get_addons_info('demo');
    if (empty($info) || empty($info['status'])) {
        return '';
    }
    // 按需过滤应用与动作
    if (app('http')->getName() !== 'admin' || !in_array($this->request->action(), ['index', 'edit'], true)) {
        return '';
    }
    return "require(['admin/js/demo/demo.dial'], function () {}, function () {});";
}
```

- **【核心调用点位置】** `app/admin/view/layout/default.html` 中 `{:hook('adminLayoutScripts')}`（常驻布局，插件安装/卸载均不影响其存在）
- **【参考实现】** `addons/call/Plugin.php::adminLayoutScripts()`（编辑页 input-tel 拨号图标 + 列表页 cell-tel 号码单元格，权限条件 `call.call_task/add`）

##### ② apiMenuItems（API 菜单数据）

- **【钩子名称】** `apiMenuItems`
- **【触发时机】** 手机端"功能列表"页请求 `crm.dashboard/getMenuAuth` 接口时
- **【参数说明】** `$admin`：当前登录管理员信息数组（含 `admin_id`/`group_id` 等，由核心触发时传入）
- **【返回值约定】** array 菜单项数组，每项结构 `{name, url, icon, customPrefix, color, auth}`，其中 `auth` 为 0/1 数值（由插件按自身权限节点计算，前端据此控制显隐）；无菜单时返回 `[]`
- **【插件注册示例】**（`addons/demo/Plugin.php`）：

```php
public function apiMenuItems($admin)
{
    // 插件未启用时不注入菜单
    $info = get_addons_info('demo');
    if (empty($info) || empty($info['status'])) {
        return [];
    }
    return [[
        'name'         => '演示模块',
        'url'          => 'packageDemo/pages/index/index',
        'icon'         => 'grid',
        'customPrefix' => 'uicon',
        'color'        => '#128F76',
        'auth'         => function_exists('auth') ? (int)auth('demo.index/index', $admin) : 0,
    ]];
}
```

- **【核心调用点位置】** `app/api/controller/crm/Dashboard.php` 的 `getMenuAuth()`：`Event::trigger('apiMenuItems', $this->admin)` 收集并合并所有监听者返回的菜单项，经响应 `menus` 字段输出
- **【前端消费】** `crm_uniapp/packageAdmin/pages/more/index.vue` 的 `allRegionList` 将 `res.menus` 并入功能列表，`auth == 1` 时显示
- **【参考实现】** `addons/call/Plugin.php::apiMenuItems()`

#### 9.5.4 手机端公共钩子（前端 App 生命周期）

手机端钩子由核心常驻分发器 `crm_uniapp/common/app-hooks.js` 提供：

- `registerAppHooks(name, fn)`：插件注册钩子处理函数（同名钩子可注册多个，按注册顺序执行）
- `invokeAppHooks(name, params)`：核心生命周期调用点（App.vue 常驻调用）
- 单个钩子执行异常仅打印警告，不阻断其他钩子与核心生命周期

##### ① appLaunch（App 启动）

- **【钩子名称】** `appLaunch`
- **【触发时机】** uni-app `App.vue` 的 `onLaunch` 生命周期
- **【参数说明】** `options`：uni-app 启动参数对象（scene/query 等，原样透传）
- **【插件注册示例】**（插件源 `addons/demo/uniapp/common/plugins/demo.js`）：

```javascript
import { registerAppHooks } from '@/common/app-hooks.js'

registerAppHooks('appLaunch', function (options) {
  // App 启动初始化：长连接、全局监听等
})
```

- **【核心调用点位置】** `crm_uniapp/App.vue` 的 `onLaunch` 中 `invokeAppHooks('appLaunch', options)`
- **【参考实现】** `addons/call/uniapp/common/plugins/call.js`（启动 WSS 长连接 + fhx-call 全局呼叫管理）

##### ② appShow（App 回到前台）

- **【钩子名称】** `appShow`
- **【触发时机】** uni-app `App.vue` 的 `onShow` 生命周期
- **【参数说明】** `options`：uni-app onShow 参数对象（原样透传）
- **【插件注册示例】** 与 appLaunch 同式；平台判断由插件注册逻辑自行处理：

```javascript

registerAppHooks('appShow', function (options) {
  // App 回到前台处理
})
// #endif
```

- **【核心调用点位置】** `crm_uniapp/App.vue` 的 `onShow` 中 `invokeAppHooks('appShow', options)`
- **【参考实现】** `addons/call/uniapp/common/plugins/call.js`（前台补传录音/补报任务结果）

##### ③ appHide（App 退后台）

- **【钩子名称】** `appHide`
- **【触发时机】** uni-app `App.vue` 的 `onHide` 生命周期

- **【插件注册示例】** 与 appShow 同式：`registerAppHooks('appHide', function () { ... })`

#### 9.5.5 事件钩子 ssoTokenIssued（单点登录推送）

- **【钩子名称】** `ssoTokenIssued`
- **【触发时机】** 手机端登录成功签发新 `token_id` 后（`login/index` 与 `login/scan` 两处；SSO 机制见 7.1）
- **【参数说明】** 数组 `['admin_id' => int, 'token_id' => string]`（新签发 token 对应的管理员与 token_id）
- **【返回值约定】** void；监听者内部异常应静默降级（核心登录流程不受影响）
- **【插件注册示例】**（`addons/demo/Plugin.php`）：

```php
public function ssoTokenIssued($params)
{
    $params = is_array($params) ? $params : [];
    $adminId = (int)($params['admin_id'] ?? 0);
    $tokenId = (string)($params['token_id'] ?? '');
    if ($adminId <= 0 || $tokenId === '') {
        return;
    }
    // 插件业务：踢掉该管理员 token_id 不匹配的旧设备连接等
}
```

- **【核心调用点位置】** `app/api/controller/Login.php` 的 `index()`/`scan()`：`\think\facade\Event::trigger('ssoTokenIssued', ['admin_id' => ..., 'token_id' => ...])`
- **【参考实现】** `addons/call/Plugin.php::ssoTokenIssued()`（通知 WSS 进程踢掉旧设备长连接）
- **【注意】** 无监听者时 `Event::trigger` 静默返回，插件未安装不影响登录

#### 9.5.6 命名规范约定

公共钩子统一采用**"场景描述式"命名（不含插件名前缀）**，与后台 `adminLayoutScripts` 模式一致：

| 类型 | 命名前缀 | 已有钩子 |
|------|---------|---------|
| 后台布局钩子 | 场景描述名 | `adminLayoutScripts` |
| 前端 App 生命周期钩子 | `appXxx` | `appLaunch` / `appShow` / `appHide` |
| API 数据钩子 | `apiXxx` | `apiMenuItems` |
| 事件钩子 | 场景描述名 | `ssoTokenIssued` |

新钩子按上述前缀规则命名，保证跨插件共用同一钩子点，避免各插件自建专属命名导致核心文件反复修改。

#### 9.5.7 插件注册文件加载约定（uni-app 前端）

**编译期限制**：uni-app 打包时 `require` 必须静态声明，核心运行时无法自动发现插件注册文件，因此各插件的 `common/plugins/{name}.js` 注册文件由插件补丁注入加载声明。

- **补丁注入（安装时）**：marker 标记补丁在 `crm_uniapp/common/app-hooks.js` 末尾的"插件注册声明区"注入一行 require（参考 `patches/app_hooks_js.json`）：

```json
{
    "type": "marker",
    "target": "crm_uniapp/common/app-hooks.js",
    "marker": "addon:call",
    "inserts": [{
        "anchor": "// ==== 插件注册声明区（由插件补丁注入 require 行，卸载时移除） ====",
        "position": "after",
        "content": "\n// ==== addon:call BEGIN ====\nrequire('@/common/plugins/call.js')\n// ==== addon:call END ===="
    }]
}
```

- **补丁回滚（卸载时）**：`AddonLifecycle::revertPatches()` → `revertMarkerPatch()` 按 `==== {marker} BEGIN/END ====` 标记块正则移除注入内容；标记不存在时跳过（幂等安全，重复卸载不报错）
- **文件归属**：插件注册文件双副本——源文件 `addons/{name}/uniapp/common/plugins/{name}.js` 经 `file_map.json` 在安装时移动至 `crm_uniapp/common/plugins/{name}.js`，卸载时移回
- **核心调用点常驻**：App.vue 的 `invokeAppHooks` 调用与 app-hooks.js 分发器为核心常驻代码，插件未安装/禁用时注册表为空、钩子空转，不影响核心启动流程

### 9.10 插件补丁（patches）从 0 到 1 开发指南

插件文件按归属可分为两类：

| 文件类型 | 说明 | 管理机制 |
|---------|------|---------|
| **插件自有文件** | `app/`、`public/`、`uniapp/` 目录下，随插件打包分发的文件 | 安装时整体移入项目、卸载时按 `file_map.json` 移回（见 9.2） |
| **补丁修改文件** | 主项目**已存在**的文件，插件只需往其中**插入/追加一段**内容 | `patches/` 目录下的 `*.json` 声明式补丁，安装注入、卸载移除 |

补丁解决的核心矛盾是：当插件需要向主项目已有文件（如 `config/log.php`、`crm_uniapp/pages.json`、`public/static/admin/js/index.js`）注入少量代码时，不能整体覆盖，否则会破坏主项目代码。补丁机制让插件作者**只声明"往哪插、插什么"**，由框架负责安全的增删。

#### 9.10.1 补丁机制原理

- **位置**：插件目录 `addons/{name}/patches/` 下，每个 `*.json` 文件定义一个补丁
- **执行时机**：
  - 安装：`AddonLifecycle::install()` 第三阶段调用 `applyPatches()`（`app/admin/service/AddonLifecycle.php`）
  - 卸载：`uninstall()` 第零阶段调用 `revertPatches()`
  - 安装中途失败回滚：`install()` 的 catch 分支会先 `revertPatches()` 再移回文件
- **三个硬性约定**（违背其一即出错）：
  1. **幂等**：已应用过的补丁自动跳过（重复安装不会重复注入）
  2. **可回滚**：注入内容必须带有可识别的标记/键，卸载时据此精准移除，无残留
  3. **失败阻断**：`applyPatches()` 校验失败会抛异常中止安装；`revertPatches()` 失败只记日志、不阻断卸载

#### 9.10.2 三种补丁类型总览

框架支持三种补丁类型，按目标文件结构选择：

| `type` | 适用场景 | 目标文件结构 | 注入方式 | 卸载移除方式 |
|--------|---------|-------------|---------|-------------|
| `marker` | 任意文本文件（PHP/JS/配置文件）插入代码块 | 文本 | 在锚点前后插入带 `==== BEGIN/END ====` 标记的块 | 按标记块正则删除 |
| `json_structure` | 向 JSON 数组追加元素 | JSON 数组（顶层键） | 追加 `item` 到数组 | 按 `match_key` 匹配删除 |
| `json_object` | 向 JSON 对象写入键 | JSON 对象（支持多级路径） | 写入 `object_path.key` | 删除该键 |

#### 9.10.3 marker 标记补丁（通用文本注入）

**字段定义**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `type` | 是 | 固定 `"marker"` |
| `target` | 是 | 目标文件相对项目根目录的路径（如 `config/log.php`） |
| `marker` | 是 | 唯一标记名，建议 `addon:{插件名}`，用于 BEGIN/END 与卸载匹配 |
| `inserts` | 是 | 插入点数组，可一次定义多个插入点 |
| `inserts[].anchor` | 是 | 锚点：目标文件中已存在的、唯一的一段文本，作为插入位置的定位依据 |
| `inserts[].position` | 是 | `"before"`（锚点前）或 `"after"`（锚点后），缺省 `"after"` |
| `inserts[].content` | 是 | 待插入内容，**必须**以 `// ==== {marker} BEGIN ====` 开头、`// ==== {marker} END ====` 结尾包裹 |

**通用模板**（向 `config/log.php` 注入一个日志通道）：

```json
{
    "type": "marker",
    "target": "config/log.php",
    "marker": "addon:demo",
    "inserts": [
        {
            "anchor": "// 其它日志通道配置",
            "position": "before",
            "content": "// ==== addon:demo BEGIN ====\n        'demo' => [\n            'type'           => 'File',\n            'path'           => '',\n            'single'         => 'demo',\n            'apart_level'    => [],\n            'max_files'      => 30,\n        ],\n        // ==== addon:demo END ====\n        "
        }
    ]
}
```

**关键点**：

- **锚点唯一性**：框架用字符串首映匹配定位（`findAnchorOffset`，先精确匹配、失败后再按 `\r?\n` 兼容 CRLF），因此锚点必须选目标文件中**明确存在且基本唯一**的片段，否则会插进第一处匹配点。锚点内换行按 `\n` 书写即可，框架自动兼容 Windows CRLF。
- **content 必须自带 END/END 标记**：卸载靠正则 `/\/\/ ==== {marker} BEGIN ====.*?\/\/ ==== {marker} END ====/` 删除标记块，若 content 缺失标记，卸载后代码残留。
- **幂等**：目标文件已包含 `==== {marker} BEGIN ====` 时直接跳过，不重复注入。
- **注释风格建议**：content 顶部可用注释说明用途与"卸载时由框架移除"，便于运维排查（参考 `addons/call/patches/log_php.json` 的写法）。

#### 9.10.4 json_structure 结构补丁（JSON 数组追加）

**字段定义**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `type` | 是 | 固定 `"json_structure"` |
| `target` | 是 | 目标 JSON 文件相对路径（如 `crm_uniapp/pages.json`） |
| `array_path` | 是 | 目标数组的**顶层键名** |
| `match_key` | 是 | 用 `item` 中哪个字段判断"是否已存在"，避免重复追加 |
| `item` | 是 | 要追加到数组末尾的元素 |

**通用模板**（向 `pages.json` 注册一个分包）：

```json
{
    "type": "json_structure",
    "target": "crm_uniapp/pages.json",
    "array_path": "subPackages",
    "match_key": "root",
    "item": {
        "root": "packageDemo",
        "pages": [
            {
                "path": "pages/index/index",
                "style": {
                    "navigationBarTitleText": "演示模块"
                }
            }
        ]
    }
}
```

**关键点**：

- **array_path 仅支持顶层键**：框架用 `$data[$path]` 直接取顶层键，不支持点号多级路径；若数组嵌套较深，需改用 marker 补丁处理。
- **幂等**：遍历数组，已存在 `item[match_key]` 与某元素 `match_key` 值相等时跳过；卸载则按 `match_key` 匹配删除并重排索引。
- **JSON 格式化**：写回时以 tab 缩进，与 `pages.json` 原格式保持一致。

#### 9.10.5 json_object 对象补丁（JSON 对象写键）

**字段定义**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `type` | 是 | 固定 `"json_object"` |
| `target` | 是 | 目标 JSON 文件相对路径（如 `crm_uniapp/manifest.json`） |
| `object_path` | 是 | 点号分隔的多级对象路径（如 `app-plus.nativePlugins`） |
| `key` | 是 | 要在该对象节点写入/删除的键名 |
| `value` | 是 | 写入的键值；框架以对象模式读取，可保留空对象 `{}` 与嵌套结构 |

**通用模板**（向 `manifest.json` 注入原生插件声明）：

```json
{
    "type": "json_object",
    "target": "crm_uniapp/manifest.json",
    "object_path": "app-plus.nativePlugins",
    "key": "fhx-demo",
    "value": {
        "__plugin_info__": {
            "name": "fhx-demo",
            "description": "原生插件说明",
            "platforms": "Android"
        }
    }
}
```

**关键点**：

- **object_path 支持多级路径**：框架按 `.` 逐级定位节点（`resolveJsonPathNode`），如 `app-plus.nativePlugins` 会最终落到 `nativePlugins` 节点上写键。
- **空对象保留**：`value` 从原始补丁文件以 `stdClass` 对象模式读取，`{}` 不会被 `json_decode(assoc)` 转空数组导致丢失。
- **兼容块注释**：`manifest.json` 含 HBuilderX 生成的 `/* ... */` 注释，框架解析前自动剥离，无需手工清理。
- **幂等**：节点已存在该键时跳过；卸载删除该键。

#### 9.10.6 从 0 到 1 开发一个补丁的完整步骤

1. **确定改动点**：明确要对主项目哪个已有文件、插入/追加什么内容
2. **选择补丁类型**：文本文件 → `marker`；JSON 数组 → `json_structure`；JSON 对象键 → `json_object`（对照 9.10.2 表）
3. **新建补丁文件**：在 `addons/{name}/patches/` 下创建 `*.json`，命名建议 `{目标文件名标识}.json`（如 `log_php.json`、`pages_json.json`）
4. **确定定位点**：`marker` 选锚点文本 / `json_structure` 定 `array_path`+`match_key` / `json_object` 定 `object_path`+`key`
5. **编写补丁内容**：`marker` 编写 content 并包裹 BEGIN/END 标记；`json_*` 编写 item/value
6. **本地校验**：先把 content 或 item 手动贴进目标文件，确认语法正确、与目标文件结构匹配
7. **安装验证**：后台上架/安装插件触发 `applyPatches()`，检查目标文件是否按预期注入、无报错
8. **卸载验证**：卸载插件触发 `revertPatches()`，检查注入内容是否无残留；重复安装-卸载各一次，确认幂等与回滚都正常

#### 9.10.7 常见错误与排查

| 报错 / 现象 | 原因 | 解决 |
|------------|------|------|
| `插件补丁格式错误` | 补丁 JSON 缺 `type` 或 `target` | 补齐必填字段 |
| `补丁目标文件不存在` | `target` 相对路径拼错或主项目无此文件 | 核对目标文件真实路径 |
| `补丁锚点未找到 (...)` | `anchor` 与目标文件实际内容不一致（缩进/换行/代码已改动） | 以目标文件当前内容重新抄取锚点 |
| `插件补丁缺少 inserts` | marker 补丁没有 `inserts` 数组 | 补 `inserts` |
| `插件补丁类型不支持` | `type` 拼写错误 | 仅支持 `marker`/`json_structure`/`json_object` |
| `插件补丁数组路径无效` | `array_path` 非顶层键或不存在 | 确认 JSON 顶层键名 |
| `插件补丁对象路径无效` | `object_path` 中间节点不存在 | 逐级核对路径 |
| `插件补丁缺少 value` | json_object 补丁未写 `value` | 补 `value` |
| 卸载后目标文件残留代码 | marker content 漏写 BEGIN/END 标记 | 补全标记后重装再卸载 |
| 重复安装出现重复内容 | 修改过 `marker` 名 / `item[match_key]` 值，导致幂等判断失效 | 保持标识稳定不变 |

#### 9.10.8 最佳实践

- **marker 命名**统一 `addon:{插件名}`，避免多插件补丁互相冲突、卸载误删
- **优先 marker 而非整体覆盖**：需要整体替换的文件应走 `uniapp/` 目录 + `file_map.json` 移动机制，补丁只做增量
- **content/item 中带注释**：说明本段用途与"卸载时自动移除"，降低运维排查成本
- **锚点选稳定的、语义明确的片段**（如固定注释行或结构名），避免随主项目迭代而失效
- **补丁失败会阻断安装并回滚**，因此发布前务必在目标版本上实测一次安装+卸载闭环

### 9.11 插件从 0 到 1 开发通用教程

本章以开发一个名为 `demo` 的新插件为例，串起从建目录到安装验证的完整流程。每个步骤集中给出"该建什么、写成什么样、与哪些既有小节相呼应"，细节定义则指引到 9.2～9.10 对应小节，避免重复。

#### 9.11.2 第一步：规划与命名

- **插件名规范**：`name` 只能由字母和数字组成（框架校验 `/^[a-zA-Z0-9]+$/`），需与 `addons/` 下的目录名、`Plugin.php` 的命名空间、`info.json` 的 `name` 三者一致，例如 `demo`。
- **划分文件归属**（这是插件设计的第一决策，决定文件放哪）：
  - 插件**独有**的完整文件（控制器、模型、视图、JS 等）→ 放 `app/`、`public/`、`uniapp/`，安装时整体移入项目、卸载时移回（9.2）
  - 需往主项目**已有文件里插一段**（注入菜单、命令、配置、路由、App 钩子等）→ 用 `patches/` 补丁声明（9.10）
  - 需要建的数据表 → `install.sql`，表名用 `addon_demo_` 前缀（9.2）

#### 9.11.3 第二步：创建目录骨架与 info.json

新建一个**最小可安装**插件，只需 `Plugin.php` + `info.json` 两个文件，其余按需补充：

```
addons/demo/
├── Plugin.php          # 必需：插件主类
├── info.json           # 必需：插件信息
├── menu.php            # 可选：后台菜单
├── install.sql         # 可选：建表 + 权限节点
├── uninstall.sql       # 可选：删表
├── config.php          # 可选：配置结构（见 9.9）
├── config.html         # 可选：配置页视图（is_set=1 时提供）
├── patches/            # 可选：补丁目录（见 9.10）
├── app/                # 可选：后端代码，安装后移动至项目 app/
├── public/             # 可选：静态资源，安装后移动至项目 public/
└── uniapp/             # 可选：手机端，安装后移动至项目 crm_uniapp/
```

`info.json` 模板（字段说明见 9.3，`require_php`/`require_crm`/`max_crm` 为可选兼容性声明）：

```json
{
    "name": "demo",
    "title": "演示插件",
    "description": "插件功能简述",
    "author": "开发者名",
    "website": "",
    "version": "1.0.0",
    "status": 0,
    "install": 0,
    "require_php": "8.0.0",
    "is_set": 0
}
```

#### 9.11.4 第三步：编写 Plugin.php 主类

主类继承 `think\Addons`，命名空间 `addons\demo`。生命周期钩子返回 `true` 表示成功；基类外的 public 方法会被 think8-addons 自动注册为事件钩子（9.4、9.5）：

```php
<?php

namespace addons\demo;

use think\Addons;
use think\facade\Cache;

class Plugin extends Addons
{
    public function install()   { $this->clearHooksCache(); return true; }
    public function uninstall() { $this->clearHooksCache(); return true; }
    public function enabled()   { $this->clearHooksCache(); }
    public function disabled()  { $this->clearHooksCache(); }

    // 业务钩子示例：向后台布局注入脚本（触发点 app/admin/view/layout/default.html）
    public function adminLayoutScripts()
    {
        $info = get_addons_info('demo');
        if (empty($info) || empty($info['status'])) {
            return '';
        }
        return "require(['admin/js/demo/demo.js'], function () {}, function () {});";
    }

    // 非 debug 模式下钩子注册表有缓存，安装/卸载/启停后必须清除
    protected function clearHooksCache()
    {
        try {
            Cache::delete('hooks');
        } catch (\Throwable $e) {
            // 忽略缓存删除失败
        }
    }
}
```

#### 9.11.6 第五步：编写 install.sql / uninstall.sql

**表命名规范**（9.2）：新插件数据表必须以 `addon_{插件名}_` 为前缀，`ymwl_` 为占位前缀、安装时自动替换成实际表前缀。时间字段遵循项目规范：`create_time`/`update_time` 用 `bigint(20) unsigned` 存 Unix 时间戳。

`install.sql` 模板（建表 + 权限节点）：

```sql
CREATE TABLE IF NOT EXISTS `ymwl_addon_demo_log` (
    `id` int(11) unsigned NOT NULL AUTO_INCREMENT,
    `admin_id` int(11) NOT NULL DEFAULT '0' COMMENT '操作人ID',
    `content` varchar(255) NOT NULL DEFAULT '' COMMENT '内容',
    `create_time` bigint(20) unsigned NOT NULL DEFAULT '0' COMMENT '创建时间',
    `update_time` bigint(20) unsigned NOT NULL DEFAULT '0' COMMENT '更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_admin` (`admin_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='演示日志表';

-- 权限节点：href 格式 {插件名}.{控制器}/{动作}；plugin=插件名（卸载时随菜单清理）
-- authopen=1 参与角色勾选；authopen=0 登录即可调用、无需勾选（如上报/上传类接口）
INSERT INTO `ymwl_auth_rule` (`href`,`title`,`type`,`status`,`authopen`,`plugin`,`pid`,`sort`,`menustatus`,`target`) VALUES
('demo.index/index','演示列表',1,1,1,'demo',0,0,0,'_self'),
('demo.index/add','新增演示',1,1,1,'demo',0,0,0,'_self'),
('demo.index/edit','编辑演示',1,1,1,'demo',0,0,0,'_self'),
('demo.index/delete','删除演示',1,1,1,'demo',0,0,0,'_self');
```

`uninstall.sql` 只负责删表（`auth_rule` 节点由框架按 `plugin` 标记统一清理，无需手写）：

```sql
DROP TABLE IF EXISTS `ymwl_addon_demo_log`;
```

#### 9.11.7 第六步：编写后台代码与静态资源

后台代码放 `app/admin/`，安装后按同名路径移动至项目 `app/admin/`，因此**命名空间统一写项目侧路径**（`app\admin\...`），控制器继承 `app\common\controller\AdminController`。

`addons/demo/app/admin/controller/demo/Index.php`：

```php
<?php

namespace app\admin\controller\demo;

use app\common\controller\AdminController;
use think\App;

class Index extends AdminController
{
    public function __construct(App $app)
    {
        parent::__construct($app);
        $this->model = new \app\admin\model\DemoLog();
    }

    /**
     * @NodeAnotation(title="列表")
     */
    public function index()
    {
        if ($this->request->isAjax()) {
            list($page, $limit, $where, $sort) = $this->buildTableParames();
            $list  = $this->model->where($where)->order($sort)->page($page, $limit)->select();
            $count = $this->model->where($where)->count();
            return json(['total' => $count, 'rows' => $list]);
        }
        return $this->fetch();
    }
}
```

配套文件建议同时创建：

```
addons/demo/app/admin/model/DemoLog.php                       # 模型
addons/demo/app/admin/view/demo/index/index.html             # 列表视图（控制器/动作 与路径对应）
addons/demo/public/static/admin/js/demo/demo.js             # 静态资源，安装后到 public/static/admin/js/demo/
addons/demo/app/admin/command/DemoCmd.php                    # （可选）think 命令，注册见 9.11.11
```

#### 9.11.8 第七步：编写 API 代码

API 控制器放 `app/api/controller/{插件名}/`，继承 `app\api\controller\Authority`（带登录鉴权），接口路径为 `api.php/{插件名}.{控制器}/{动作}`：

```php
<?php

namespace app\api\controller\demo;

use app\api\controller\Authority;
use think\App;

class Index extends Authority
{
    public function __construct(App $app)
    {
        parent::__construct($app);
    }

    public function index()
    {
        return json(['code' => 1, 'msg' => '', 'data' => ['hello' => 'demo']]);
    }
}
```

跨端共用的业务逻辑放 `app/common/service/`（如 `DemoService.php`），后台与 API 共享调用，避免重复代码。

#### 9.11.9 第八步：手机端集成（uniapp）

手机端文件放 `uniapp/`，安装时整体移动至项目 `crm_uniapp/`。关键约定：

1. **插件注册文件** `addons/demo/uniapp/common/plugins/demo.js`：经 `registerAppHooks` 注册 App 生命周期钩子（9.5.4）：

```javascript
import { registerAppHooks } from '@/common/app-hooks.js'

registerAppHooks('appLaunch', function (options) {
  // demo 插件启动初始化
})
```

2. **注入 require 声明**：uni-app 打包要求 `require` 静态声明，需用 marker 补丁在 `crm_uniapp/common/app-hooks.js` 末尾注入 `require('@/common/plugins/demo.js')`（9.5.7，样式见 9.10.3）
3. **注册分包路由**：新页面放在独立分包 `packageDemo/`，用 `json_structure` 补丁写入 `crm_uniapp/pages.json` 的 `subPackages`（9.10.4）
4. **原生插件**（可选）：`uniapp/nativeplugins/{插件}/` 放 .aar 等，用 `json_object` 补丁写入 `manifest.json` 的 `app-plus.nativePlugins`（9.10.5）
5. **菜单入口**：如需进手机端"功能列表"，在 `Plugin.php` 实现 `apiMenuItems($admin)` 钩子返回菜单项（9.5.3 ②）

#### 9.11.10 第九步：编写补丁 patches/

需要改主项目已有文件时，在 `patches/` 下创建对应 `*.json` 补丁文件。三种类型（marker / json_structure / json_object）的选择、字段与模板，完整见 **9.10**。常见补丁清单：

| 需求 | 补丁类型 | 目标文件 |
|------|---------|---------|
| 注入 App 生命周期 require | `marker` | `crm_uniapp/common/app-hooks.js` |
| 注册手机端分包 | `json_structure` | `crm_uniapp/pages.json` |
| 声明原生插件 | `json_object` | `crm_uniapp/manifest.json` |
| 注册 think 命令 | `marker` | `config/console.php` |
| 注入后台框架 JS（如弹窗客户端） | `marker` | `public/static/admin/js/index.js` |
| 注入独立日志通道 | `marker` | `config/log.php` |
| 后台页面脚本增强 | `marker` | 对应业务 JS（如 `public/static/admin/js/xxx.js`） |

#### 9.11.11 第十步：配置与命令注册

**插件配置**（9.9）：`addons/demo/config.php` 定义配置结构 + 默认值，后台设置页读取；用户修改值存 `ymwl_addon_config` 表、优先生效。业务代码用 `get_addons_config_value('demo', '键', '默认值')` 读取：

```php
<?php
return array(
    'task_timeout' => array(
        'title' => '任务超时(秒)',
        'type'  => 'number',
        'value' => 60,
        'tip'   => '超过该时长未执行自动置超时',
    ),
);
```

若需要独立设置页面，`info.json` 置 `is_set=1` 并补充 `config.html`。

**think 命令注册**：命令类放 `addons/demo/app/admin/command/`，通过 marker 补丁往 `config/console.php` 的 `commands` 数组注入注册项（参考 `addons/call/patches/console_php.json`，用 `is_file()` 判断命令文件存在才注册，插件卸载后自动失效）：

```json
{
    "type": "marker",
    "target": "config/console.php",
    "marker": "addon:demo",
    "inserts": [
        {
            "anchor": "'app\\admin\\command\\Min',",
            "position": "after",
            "content": "\n        // ==== addon:demo BEGIN ====\n        ...(is_file(app_path() . 'admin/command/DemoCmd.php') ? ['app\\admin\\command\\DemoCmd'] : []),\n        // ==== addon:demo END ===="
        }
    ]
}
```
